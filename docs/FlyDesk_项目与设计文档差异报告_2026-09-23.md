# DeFly 项目与 FlyDesk 设计文档差异报告

核查日期：2026-09-23
项目目录：`D:\deafly`
代码版本：`7635888`

## 1. 总体结论

当前项目已经实现一部分真实业务闭环，并额外发展了浏览器全脑 WASM、三维果蝇和蝇群联邦功能。但它与所提供的 FlyDesk v1.0 设计存在产品方向、交易语义、模型训练路线和技术架构上的系统性差异，不能理解为“按原文档开发，只剩少量页面待补”。

按原文档严格判断：**尚不能认定达到 G0，更未达到 G1**。G0 所需的完整图表工具和实时人类模拟回合尚有缺口；G1 所需的真脑特征与个人决策层结合、冻结验证和规定的独立评测链路尚未对齐。这不否定现有全脑 WASM 工作，只表示它与原规格的主训练路径不同。

当前项目更准确的描述是：**历史交易带教与积分装扮原型，加上独立发展的浏览器神经模拟与自主实验平台。**

## 2. 对照材料与核查边界

对照材料为下载目录 `FlyDesk_Design_v1` 中的三份文件：

- `02_Product_Guide.md`：产品目标和用户体验。
- `02_Product_Guide.docx`：已提取全部正文及表格文字，与 Markdown 的主要内容一致；未发现需求层面的实质差异。此次不评估 Word 排版。
- `03_Codex_Technical_Spec.md`：模型路线、接口、数据规则、默认参数及验收标准。

文档均描述拟实现系统。其中“必须实施”“执行顺序”等文字只作为本次差异比较的依据，不视为用户要求立即改代码。文档中的推荐技术栈和工程默认值，也与产品硬边界分开评价。

本报告依据当前本地源码、数据库迁移、测试及项目文档。未访问线上站点、修改部署或核验远程生产数据库；没有运行原生 Python 神经核、浏览器全流程、完整性能测试。历史报告和已有实验产物仅作为参考，不当作本次重新验证的结果。未对外部接口和许可的最新状态作结论。

## 4. 最需要注意的几处差异

### 4.1 交易语义改变了训练任务本身

`raising-core.mjs` 第 2 行把空仓动作设为 BUY/SELL/HOLD，持仓动作设为 HOLD/CLOSE；`execute()` 中 SELL 会建立 SHORT。这与文档第 7 章和 A06 的“不做空”直接冲突。

此外，现有模型训练输出也包括 CLOSE。若未来回归原规格，需要版本化处理已有示范：旧 SELL 不能直接当成新规则下的“减仓”，旧 CLOSE 也不能不加区分地合并成 SELL。撮合、训练、评测和 UI 必须共同调整。

### 4.2 两种模型都有代码，但还没有组成文档要求的一个闭环

个人训练路径是 `market_only_readout_v1`。代码实际计算梯度、更新参数、保存哈希与候选版本，并有训练前后评测；因此不能说它“只是随机演示”或“没有训练”。

浏览器神经路径是 `stonkfly-full-browser-wasm-v1`。当前目录含 `kernel.wasm`、数据分片、manifest、输入编码器和检查点模块。manifest 声明 166,700 个节点和 25,582,938 条边；这些是资源清单记录，本次未重新做全图完整性或原生等价验证。

关键差距是：个人 head 训练未消费该神经核产生的 256 桶特征，也未采用文档的 336 维混合输入。浏览器采用 320×180 收盘价线图编码，普通 OBSERVE 推进 100ms，强化路径推进 500ms，与文档每观察 500ms、三周期价格/量能输入不同。`brain.mjs` 还包含学习状态推进和可塑权重计算，不能直接认定满足 G1 的逐数组冻结要求。

服务端对浏览器自主结果明确记录 `browser_asserted_untrusted`、`server_verified_kernel:false`。这说明服务端目前并不证明客户端确实执行了指定神经核。浏览器方案可以继续研究，但其验证与反作弊边界需要独立设计。

证据：[浏览器编码与客户端](../pages/browser-brain-client.js)、[神经 Worker](../pages/full-brain/worker.mjs)、[脑运行时](../pages/full-brain/brain.mjs)、[浏览器自主协议](../worker/src/browser-autonomy.mjs)。

### 4.3 已有防泄露措施，但离完整时点协议仍有距离

当前历史回合响应只返回截至当前步可见的 bars；动作提交有 step 校验和幂等键；示范与系统期末清仓分开保存。这些都是已有的有效基础。

不过 `raising.mjs` 先调用 `advance()`，后执行数据库批事务；`advance()` 会读取下一根 open 并计算结果。文档第 6.2 节与 A14 则要求“先持久化动作，再读取未来成交数据”。当前写法并不自动证明客户端泄露，但不符合规定的事件顺序。

示范已有观察哈希、可见 bars、人类动作和执行结果，却未达到第 9.2 节完整字段合同，尤其是不可变分析版本、锁定模型版本、双时钟及 consent 信息。查看复盘 JSON 也不等于完成规定的 JSONL＋Parquet＋观察 artifacts 导出及账号删除流程。

### 4.4 数据与评测有保护，但协议已经简化

当前已存在行情暴露区间登记、重复示范规范化、持久化 split 登记和未见区间检查。这些修复不能被旧报告中的问题覆盖掉。

但当前 split 注册主要按用户保存，尚不等价于原文档“同一市场窗口跨用户统一归属同一 split”的固定数据集协议。未见规定的至少 30 天历史数据导入与统一 70/15/15 清单。训练数据达到 2000 条上限后明确拒绝，尚非文档建议的按 episode 保留方案。

评测使用下一分钟参考引擎，而教学每五分钟决策；前端对此做了明确说明。现有结果可以用于其自身实验，但不能直接当作原教学规则下的完整训练效果验收。缺少全额和一档买入持有的双基准、原始 Stonkfly 解码对照、神经特征移除对照及规定的多回合多 seed 报告。

### 4.5 项目说明也需要更新

README 的产品宣传强调浏览器完整大脑，技术限制段却仍主要描述 native G1 缺口和等待 native publication；当前代码已具备浏览器 WASM 活动通路。两者并非完全互斥，但没有清楚解释“全脑运行”与“个人带教训练”是两条不同路径，容易使读者误以为它们已经连通。

`docs/raising-spec-review.md` 是旧快照：它所列的训练按钮未传幂等键、缺少评测/激活入口、缺少暴露登记等问题，在当前代码中已有相应实现。因此本报告没有照搬旧结论。该旧文档甚至写“目录不是 Git 仓库”，也已不符合当前环境。

## 7. 后续处理建议

首先确定未来采用哪份产品基线。若继续做 DeFly 浏览器果蝇／蝇群，应修订 FlyDesk 文档，把四动作、多空账户、浏览器核和联邦功能列为正式变更，并重新定义验收；若回归 FlyDesk v1.0，则应按下列顺序收敛。

1. **先统一交易和训练语义。** 明确三动作、禁止做空、含手续费的固定额度、SKIP/TIMEOUT；为旧记录和模型设迁移或隔离规则。
2. **补产品闭环。** 完整账号登录、K 线指标与画线、指定历史时点、实时人类回合、数据导出和最小管理功能。
3. **统一账本与评测。** 精确金额、提交和成交事件顺序、固定数据集、同规则的教学与独立 rollout。
4. **明确 G1 主模型。** 选择继续实现原生适配器，或正式把浏览器核作为变更方案；无论选哪条，都要接通神经特征到个人 head、冻结验证、检查点和消融评测。
5. **整理交付证据。** 安装锁定依赖后重跑测试，修订过时报告，补环境配置和性能结果，逐项映射 A01–A42。

不建议仅为技术栈名称一致就全面重写。现有资产可以保留，但必须优先解决用户实际操作规则和模型训练协议的分歧。
