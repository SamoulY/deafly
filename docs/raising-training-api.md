# Raising Training API

Pure ES module: `worker/src/raising-training.mjs`. Backend `market_only_readout_v1` is a simplified supervised linear softmax decision head, NOT Stonkfly and NOT the original G1 neural architecture. PAPER_ONLY. No profit promises.

## Integration contract

- `ACTIONS`: `['BUY','SELL','HOLD','CLOSE']`. BUY opens long, SELL opens short, HOLD preserves state, CLOSE exits. No pyramiding.
- `FEATURE_NAMES`: fixed ordered numeric input schema; no identifiers, cosmetics, future returns or rewards.
- `extractFeatures({candles,account,asOf})`: closed candles (`{time,open,high,low,close,volume,closed:true}`) only, time <= asOf, strictly increasing. Account `{cash,initial_balance,position: 'FLAT'|'LONG'|'SHORT',entry_price}`. Returns numeric feature array.
- `actionMask(account)`: boolean array; HOLD always valid, entries only flat, CLOSE only positioned.
- `createDefaultCheckpoint()`: deterministic untrained head, fixed feature coordinates and HOLD preference.
- `predict(checkpoint,features,mask)`: `{action,probabilities}`; mask required.
- `hashCheckpoint(checkpoint)`: async SHA-256 canonical JSON; JSON save/restore preserves hash.
- `trainDecisionHead({rows,parentCheckpoint?,validationFraction?,maxEpochs?,patience?,learningRate?,minDelta?})`: async, immutable input. Returns `{checkpoint,checkpoint_hash,parent_hash,metrics,split_manifest,data_hash}`. Rows `{features,action,time,session_id,observation_hash,training_eligible,action_mask?,interval_start?,interval_end?}`. Only explicitly eligible rows enter; adapter MUST authenticate ownership and establish replayability/explicit human intent before setting eligible. Full scenario context/warmup/reward/settlement boundaries MUST populate intervals (defaults are point observations, not a claim of scenario independence). Entire sessions remain in one split. At least 64 training, 16 validation, two training classes with >=8 examples each. No row replication. Default validation fraction .2. Strict chronology and nonoverlap across splits. Parent feature coordinates are unchanged on continuation. Full personal replay dataset supplied by caller. Continuation preserves each parent observation hash's train/validation assignment and rejects reassignment even when replay timestamps change. Omitted action masks are inferred from `cash_ratio` and `position_side`: entry requires positive cash and a flat position; CLOSE requires a position; HOLD remains valid. Explicit masks retain their existing contract and must be authoritative masks supplied by the adapter. `usedIntervals?: [{start,end}]` rejects any eligible scenario touching a reserved evaluation interval.
- `evaluateFrozen({preCheckpoint,postCheckpoint,trainingManifest,candles,usedIntervals,initialBalance?,feeBps?,slippageBps?,notionalFraction?})`: async deterministic, no updates/intervention. Future candles must begin after BOTH checkpoints' seen-data bounds and manifest validation interval. Mandatory `usedIntervals: [{start,end}]` reserves previously exposed evaluation periods; overlapping periods rejected. Parent must atomically reserve returned interval in D1 before reporting and reuse that registry for subsequent train/eval eligibility. Returns cash, buy_hold, pre, post metrics, frozen hashes, interval/data hash, comparison and honest status. Checkpoints cannot include intervals consumed by previous evaluation in subsequent training; caller enforces global access registry.

## Evaluation handshake

Self-contained paper evaluator deliberately does not import the concurrent `raising-core` module. All four policies use identical accounting: 1x fixed initial-balance notional, next candle open execution, signed long/short position, proportional fees and adverse slippage, final forced close. No borrowing to amplify notional, no live orders. It is an evaluation reference engine, not a claim of identical core simulator rules. Do not compare these results to core sessions unless costs/execution semantics match. Decisions use closed candle prefixes only; final close is separately forced. Net PnL, maximum drawdown (equity fraction), voluntary and forced fills per decision, next-bar direction accuracy for entries (null when undefined), and trade counts are reported. A single held-out interval cannot establish statistical improvement; status remains `NO VERIFIED IMPROVEMENT`, with measured deltas separately reported.

No persistence, network, clocks, randomness, or model activation. D1 ownership, job lifecycle, version locks, authoritative observation hashes, global split assignments, access budgets and atomic interval reservations belong to the service adapter. Use only authentic market data in production; test fixtures are synthetic scripted evidence of mechanics, not profitability.
